How the domain inspector works

Traditional ICMP ping is blocked by most cloud providers, so it rarely tells you what you want to know about a real website. This tool uses HTTP fetch timing instead — the same path your browser actually takes — and runs DNS-over-HTTPS in parallel. The result is a single, fast answer: where does this domain point, can I reach it, and how fast?

      Frequently asked questions

      What is a domain inspector?

      A domain inspector runs several common network checks against a hostname in one shot: DNS records, resolved IP addresses, HTTP reachability, response time, and TLS / server headers (when CORS allows). It is the fastest way to answer "what is going on with this website" without opening five different tools.

      How do I ping a website?

      Type the hostname (for example github.com) into the box above and press Enter. The inspector will resolve its DNS, list its IP addresses, and try to reach it over HTTP. The result is shown as reachable / unreachable / unknown, with the timing.

      What can this tool detect that a normal ping cannot?

      Traditional ICMP ping is blocked by most cloud providers (Cloudflare, AWS, Google), so it is rarely useful for testing real websites. This tool uses HTTP fetch timing instead, which works against virtually every site and gives you a result that is more representative of what your browser actually experiences.

      Why does the reachability sometimes show "unknown"?

      Some websites block cross-origin reads of their responses (CORS). When that happens, the browser still tells us the request completed — so we can usually mark the site reachable — but we cannot read the response body or status code. In that case the result shows "reachable (response not readable)".

      What is a good HTTP latency?

      Under 100 ms is excellent for most websites. 100-300 ms is typical for cross-continental connections. Over 500 ms will feel sluggish. The number you see is the full request round-trip from your browser, including DNS, TCP, TLS, and the server's response time.
