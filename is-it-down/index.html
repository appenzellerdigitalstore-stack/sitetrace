About this status checker

Paste any URL above to probe it from your browser, plus see live status indicators for 50+ popular services (Steam, GitHub, Discord, Cloudflare, OpenAI, Reddit, Twitter/X, and more) sourced directly from each service’s official Atlassian Statuspage. I built this because Downdetector’s homepage is overloaded with ads and clickbait, and most status aggregators lag the real Statuspage data by 5-15 minutes.

The reachability check runs in your browser via the standard fetch API — your computer asks the site directly, so the answer reflects your network, not some random probe. The official status indicators refresh on every page load (no background polling, no surprise CPU spikes). The Cloudflare Worker in front of the Statuspage API caches responses for 60 seconds to stay within their free tier rate limits.

For programmatic bulk checks (from CI, from a monitoring system, from a server), the same logic is exposed via api.sitetrace.it.com/api/status-check — free tier allows 5 URLs per call, paid tiers up to 100.

Frequently asked questions

How do I check if a website is down for me?

Paste the URL (e.g. https://github.com) into the search box at the top of this page and press Check. The tool will probe the site from your browser, show whether it is reachable from your network, and link you to the service’s official status page if we track it. The browser-based check runs in under 2 seconds for most URLs.

What is the difference between “down for me” and “down for everyone”?

“Down for me” means your connection cannot reach the service, but the service itself is fine for everyone else — usually a problem with your network, ISP, DNS, or VPN. “Down for everyone” means the service has declared an outage or degradation on its official status page, affecting all (or many) users. The two require very different responses: a personal outage usually means restarting your router or VPN; a global outage means waiting for the service to fix it.

Where does the data come from?

The reachability check runs in your own browser — your computer asks the site directly via HEAD or GET request. The official status indicators come from each service’s status page (mostly Atlassian Statuspage) via their public JSON APIs, queried through a Cloudflare Worker that handles CORS and rate limiting. We do not guess or infer outages from user reports. The 24-hour incident timeline comes from the same Statuspage source.

What if my browser says the site is reachable but the page is broken?

That can happen for several reasons. Cross-origin restrictions (CORS) sometimes make the response unreadable, so the tool can confirm the site responds but cannot read the body. Try opening the site directly in a new tab. If the service is in our tracker, also check its official status — there may be a partial outage affecting only some features (login, API, search, etc.) while others work.

How often is the status data updated?

When you load the page, every service is fetched in parallel (with a small concurrency cap to respect the public API rate limits). The result you see is at most a few seconds old. There is no background polling — every refresh is fresh. The Cloudflare Worker caches responses at the edge for 60 seconds to keep API usage within Statuspage’s free tier limits.

Why do some services show “unknown” status?

Either the service’s status page returned an error (rare — usually a brief outage on their end), the service doesn’t have a public status page we can query, or the Cloudflare Worker hit a rate limit. Refresh the page in 30 seconds and the status should appear. If a service consistently shows unknown, that service likely uses a custom status page not compatible with the Statuspage JSON API.

Can I check multiple URLs at once?

Not from this page, but the same logic is available as a bulk endpoint via the sitetrace-api. POST a list of URLs to /api/status-check and you get back each URL’s status, response time, and content-type. Free tier allows 5 URLs per call, paid tiers up to 100.

Is the reachability check from my browser accurate?

It tells you whether your browser can reach the site — which is the most useful question from your perspective. It does not tell you whether the site is down for everyone else. For global status, rely on the official status indicators on the page (the green/yellow/red dots next to service names). CORS restrictions sometimes prevent the tool from reading the response body, but reachability alone is enough to distinguish ‘your problem’ from ‘their problem’.
