What this HTTP headers viewer does

Every HTTP response comes with a set of headers — key-value pairs the server sends before the page body. They tell your browser how to handle the response: how long to cache it, whether to allow scripts, where to redirect, what content type the body is, and so on. Some headers are security-critical (CSP, HSTS, X-Frame-Options); others leak information about the server (Server, X-Powered-By) and should be removed. This tool fetches any public URL, dumps the full response header set, and grades the security headers on a 0–100 scale.

How the security-header grade works

The grade is a 0–100 score built from six weighted security headers. Content-Security-Policy is worth 25 points and is the most commonly missed; Strict-Transport-Security is worth 20; X-Frame-Options is worth 15; X-Content-Type-Options and Referrer-Policy and Permissions-Policy are worth 10 each. A+ means 95+, A is 85–94, B is 70–84, C is 55–69, D is 40–54, and F is below 40. The grade also surfaces any Server, X-Powered-By, or version-leaking headers — these are not scored against you, but they tell an attacker what stack you run, and most security guides recommend stripping them.

HTTP response headers are the metadata your server sends with every page load. Most of them you'll never see — they're set by the server framework (Express, Rails, Spring) or a reverse proxy (Cloudflare, Apache, nginx) and the browser handles them silently. A few are security-critical; the rest control caching, content negotiation, and behavior. Here's the practical breakdown.

Caching headers. Cache-Control is the one you'll see most often. Values like max-age=3600 tell the browser to cache for an hour; no-cache means "always revalidate"; no-store means "don't cache at all" (used for sensitive content). ETag is a hash of the response that the browser sends back with conditional requests — if the resource hasn't changed, the server returns 304 Not Modified and the browser uses its cache. Last-Modified and Expires are older versions of the same idea. Vary is the one most production sites get wrong — it tells the cache "the response varies by Accept-Encoding" or "by Origin" or similar, so the cache doesn't serve the wrong version to the wrong client. For an API serving JSON to SPAs, Vary: Origin is critical.

Content negotiation. Content-Type tells the browser what's in the body — text/html; charset=utf-8, application/json; charset=utf-8, image/png. Content-Encoding says the body is encoded — usually gzip, sometimes br (Brotli). Content-Length is the body size in bytes (helpful for download progress). Content-Language is the language of the body — used by Google's hreflang signals for multilingual sites.

Security headers — the six critical ones.

Strict-Transport-Security (HSTS). Tells the browser "always use HTTPS for this domain, even if the user types http://". Value: max-age=31536000; includeSubDomains; preload. The preload directive lets you submit to Chrome's HSTS preload list, which is baked into the browser so even the first request (before any header has been received) goes to HTTPS. HSTS prevents downgrade attacks where an attacker intercepts the first HTTP request and rewrites it. Without HSTS, the first request to your site can be hijacked; with HSTS, even that first request is encrypted.

Content-Security-Policy (CSP). Tells the browser "these are the only sources of scripts, images, and connections allowed on the page." Value: default-src 'self'; script-src 'self' https://cdn.example.com; object-src 'none'; base-uri 'self'. CSP prevents most XSS attacks because even if an attacker injects a script tag, the browser refuses to load it. Most production sites run CSP in report-only mode first (CSP-RO) to discover violations without breaking the site, then tighten to enforce. A site without CSP is at materially higher XSS risk; a site with a strong CSP that breaks half the page is also not safe.

X-Frame-Options. Tells the browser "don't let anyone embed this page in an iframe." Value: DENY or SAMEORIGIN. Prevents clickjacking — where an attacker overlays a malicious button over a legitimate one in an iframe. DENY is the safer default; SAMEORIGIN allows your own site to iframe your own pages (useful for some flows). Modern alternative: frame-ancestors 'none' in CSP, which supersedes X-Frame-Options.

X-Content-Type-Options: nosniff. Tells the browser "don't guess the content type from the body — trust the Content-Type header." Without it, a text file served with Content-Type: text/plain can be interpreted as JavaScript if the contents happen to look like a script. nosniff stops the browser from doing MIME sniffing. Always set this — it's free, has no downside, and closes a real attack vector.

Referrer-Policy. Tells the browser when navigating away from your page whether to send the full URL in the Referer header. Value: strict-origin-when-cross-origin is the modern safe default. Sends the full URL on same-origin navigation, only the origin on cross-origin. no-referrer sends nothing — privacy-maximizing, but some analytics tools depend on the referrer to attribute traffic.

Permissions-Policy. Tells the browser which powerful features (camera, microphone, geolocation, USB, payment, accelerometer) are allowed on this page and on iframes. Value: camera=(), microphone=(), geolocation=() disables all three. Most sites should set this defensively to () for any feature they don't actively need. Reduces the blast radius of an injection — even if an attacker injects JavaScript, the script can't request camera access.

Headers that leak information you don't want. Server: nginx/1.21.0 tells an attacker your exact nginx version. X-Powered-By: PHP/8.1.7 is a goldmine for CVE matching. The Via header reveals every proxy in the chain. None of these are scored in the audit (security researchers know how to find versions anyway), but stripping them reduces the surface area for targeted attacks. Most web servers let you blank the version with one config line.

Setting headers in different frameworks. nginx: add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;. Apache: Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains". Express (Node.js): use the helmet middleware — app.use(helmet()) sets 12 security headers in one line. Rails: config.force_ssl = true enables HSTS. Django: SECURE_HSTS_SECONDS = 31536000 in settings.py. Cloudflare: enable HSTS in the SSL/TLS app.

The headers view behind this page fetches the URL with a HEAD request (no body downloaded) and parses the response headers with a small client. The whole round trip is under 2 seconds. The security grade is computed from the parsed header set; the breakdown shows which headers are present, missing, or weak. If you want to do it from CI:

$ curl -sI https://example.com
# → HTTP/2 200\n# server: nginx\n# content-type: text/html; charset=utf-8\n# strict-transport-security: max-age=31536000; includeSubDomains\n# ...

Or via the API: curl -X POST https://api.sitetrace.it.com/api/http-headers -H 'Content-Type: application/json' -d '{"url":"https://example.com"}' returns the parsed headers + security grade in JSON. The free tier allows 100 calls per day; paid plans allow more. For continuous monitoring, run weekly and watch for regressions — a header disappearing usually means a config change or a deployment that wiped a setting.

Frequently asked questions

What are HTTP response headers?

HTTP response headers are key-value pairs the server sends back with every page load, before the page content. They tell your browser how to handle the response: how long to cache it, whether to allow scripts, where to redirect, what content type the body is, and so on.

What is the Content-Security-Policy header?

Content-Security-Policy (CSP) is a header that tells the browser which sources of scripts, styles, images, and connections are allowed to load on the page. A well-configured CSP prevents most XSS attacks because even if an attacker injects a script tag, the browser refuses to load the source. A missing or weak CSP is one of the most common security gaps on production sites.

What is Strict-Transport-Security (HSTS)?

Strict-Transport-Security (HSTS) is a header that tells the browser to always use HTTPS for this domain, even if the user types http:// or follows an http:// link. The header includes a max-age in seconds (commonly 31536000, which is one year) and an optional includeSubDomains flag. HSTS prevents downgrade attacks and cookie theft.

Why does my site get a bad grade?

Most production sites miss one or more of the high-weight security headers. The score is a rough guide — a site with no CSP is genuinely at higher risk for XSS, but a site with a strong CSP that breaks half the page is also not safe.

Is this tool safe to use on any URL?

You can use it on any public http:// or https:// URL. Private IPs, localhost, and .local / .internal hostnames are blocked to prevent the tool from being used to scan internal infrastructure. The tool only reads response headers — it does not execute the page, does not load scripts, and does not interact with the page in any way your browser would not if you visited the URL directly.
