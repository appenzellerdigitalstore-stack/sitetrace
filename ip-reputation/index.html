What this IP reputation check does

Every public IP carries a reputation. The reputation is shaped by what kind of traffic has come from that IP before — bulk email, abuse reports, hosting scans, botnet activity. Mail servers, signup forms, and security systems check public blocklists before accepting traffic from an IP, and a single listing on the wrong list can mean your mail lands in spam or your legitimate traffic gets blocked. This tool queries seven of the most-used public blocklists in parallel, then combines the result with public geolocation and connection-type data to give you a single reputation score and a per-list breakdown.

How IP reputation checking actually works

This tool runs three checks in parallel: it queries seven of the most widely used public blocklists (DNSBLs) for the IP, it asks a public geolocation database where the IP is registered and what kind of network it belongs to, and it combines those signals into a single 0–100 reputation score. The score starts at 100, drops 10 points for every DNSBL that lists the IP, drops another 15 if the IP is flagged as a proxy, and adjusts slightly based on the network type. A score of 80+ is low risk, 50–79 is medium, and under 50 is high. The blocklist data comes straight from the lists' DNS zones, so a "listed" result here is exactly what a receiving mail server would see.

The reputation is mostly invisible until it bites you, which is why a tool like this exists.

What is a DNSBL? A DNSBL (DNS-based Blockhole List, also called a "block list" or "RBL") is a public database of IP addresses that have been observed sending spam, hosting malware, or being used for other abusive activity. Other servers can ask the list "is this IP on you?" by reversing the IP octets and looking it up in the list's DNS zone. For example, to check whether 203.0.113.42 is on the Spamhaus ZEN list, a server queries 42.113.0.203.zen.spamhaus.org as an A record. If the IP is listed, the answer is 127.0.0.x where the last octet tells you which sub-list hit (SBL, XBL, PBL). If not, the lookup returns NXDOMAIN. The whole check takes about 5-30ms per list, which is why 7-list parallel queries add up to under a second total.

Which lists matter? This tool queries seven: Spamhaus ZEN (the umbrella list combining SBL, XBL, and PBL — used by Gmail, Outlook, Postmark, Mailgun), Spamcop (community-reported spam source), CBL (Composite Blocking List — infested machines sending spam), Barracuda BRBL (commercial list from Barracuda's mail security), PSBL (passive spam block — no direct confirmation needed), SBL (Sorbs — multi-purpose blocklist with SMTP and proxy sub-lists), and UCEPROTECT level 1 (aggressive list that drops an IP if any other IP in the same /24 is). If you're listed on Spamhaus ZEN specifically, your mail is rejected by Gmail, Microsoft, Yahoo, and most SMTP servers on the internet — getting off that list is urgent. Barracuda CBL and Spamcop are similar in importance. The smaller lists (PSBL, UCEPROTECT-1) are less commonly checked but still used by some.

What's the difference between a DNSBL and a URI reputation list? DNSBLs list IP addresses. URI reputation lists (SURBL, URIBL, Invaluement URI) list URLs found in spam. The IP might be clean, but the URL in the spam message might be on SURBL — so most mail servers check both. SURBL/URIBL are beyond what the simple IP-only check this tool does; if you want URI checks too, MXToolbox's SuperTool does them in addition to DNSBL.

What aren't these tools checking? The big one: Gmail's internal reputation, Outlook.com's SmartScreen, Yahoo's internal list, Microsoft's Exchange Online Protection (EOP). All four are proprietary — there is no public DNSBL that mirrors them. If your mail lands in spam on Gmail but doesn't show up on Spamhaus or any public DNSBL, you're probably on one of these private lists, and the only fix is to send mail through a major SMTP provider (Mailgun, Postmark, SendGrid, Resend, Amazon SES) rather than your own server. Also: Microsoft Defender for Office 365's URL sandbox, Proofpoint's URL defense, Mimecast's URL protect — all proprietary.

Why does a shared hosting IP have a bad reputation? Shared hosting means thousands of sites share one or a few IPs. If one of them is sending spam, the IP gets listed, and now every other site on that IP suffers. Cheap shared hosting (HostGator, Bluehost, GoDaddy economy) often allows outgoing SMTP from any account, so a single compromised WordPress install can take down the IP for everyone. Better hosts (WPEngine, Kinsta, Cloudways) lock down outgoing SMTP and run their own mail through dedicated transactional providers. If you sign up for a $4/month shared hosting plan and your mail lands in spam, your IP reputation is probably bad and you'll get it changed by sending mail through Mailgun or Postmark on a different server, not by changing your hosting.

How to get delisted. Each list runs itself. The general steps are: (a) find the listing reason — every list has a lookup page that explains why; (b) fix the underlying problem (compromised script, open mail relay, abused contact form); (c) follow the list's delisting procedure — usually a removal request form on their site; (d) allow 24-72 hours for the change to propagate. Spamhaus is the strictest — they require manual review and proof of the fix. Spamcop auto-removes after the spam stopped arriving. CBL auto-removes when no more spam is seen for ~14 days. UCEPROTECT-1 is the hardest — they want you to pay a fee and wait, and they won't tell you which one is in the list specifically.

How the composite score here works. Start at 100. Each DNSBL listing subtracts 10. A proxy/hosting flag subtracts another 15. Mobile network subtracts 5 (because dynamic IP reassignment means the bad repute was set with the previous user of the IP). Above 90 is excellent. Below 50 is bad. The score is intentionally not scientifically rigorous — it's a quick way to see "this IP is fine" or "this IP is in trouble". If you need a finer-grained view, MXToolbox's commercial network reputation (more than $10/month) aggregates 50+ signals including ASN reputation, abuse contact reachability, and historical PTR record consistency.

The checks behind this page happen in a Cloudflare Worker that fans out the seven DNSBL queries in parallel using the DNS-over-HTTPS APIs each list publishes. The total wall-clock time is usually under 1.5 seconds. Geolocation enrichment comes from the same ip-api.com source used by /what-is-my-ip/. We don't log the IPs queried, don't store the results, and don't share them with any third party. If you want to verify from a script, the same check is at api.sitetrace.it.com:

$ curl -X POST https://api.sitetrace.it.com/api/ip-reputation -H 'Content-Type: application/json' -d '{"ip":"203.0.113.42"}'

A clean score here doesn't mean every mail server will accept your mail — Gmail's internal reputation is its own thing. A bad score here, especially with Spamhaus ZEN or Barracuda CBL hit, requires immediate delisting or your mail will stop reaching most inboxes within days. Don't wait.

Frequently asked questions

What is IP reputation?

An IP address builds a reputation based on what traffic has come from it: email sent, websites hosted, abuse reports filed. Mail servers and security systems use that reputation (combined with public blocklists) to decide whether to accept, flag, or reject traffic from the IP. A clean reputation means your email goes to inboxes and your services aren't pre-blocked. A bad reputation means your mail lands in spam, your signups get flagged, and your support inbox fills up with "I can't reach your site".

How do I get delisted from a blacklist?

Each list runs itself. First, find the listing reason (almost every list has a lookup page that explains why they listed the IP). Fix the underlying problem — a compromised script sending spam, an open mail relay, an old contact form being abused — then follow the list's delisting procedure. Most lists have a removal request form on their site. Some are automatic once the listing criteria no longer apply; others require manual review. Allow up to 24 hours after the request is processed for the change to propagate.

Is my IP address being shared with anyone?

Only if you paste it into the form yourself. The "check my own IP" button sends a request to SiteTrace's edge, which queries the public blocklists and a public geolocation database. The result comes back to your browser. SiteTrace does not log which IPs are checked, does not store the results, and does not share them with any third party.

Why does my IP show as a proxy or hosting network?

If you see "proxy" or "hosting", your IP belongs to a data-center or VPN provider, not a residential ISP. This is normal if you are on a VPN, on a corporate network, or hosting a server. Mail servers and security systems treat these IPs with extra suspicion because they are commonly abused — but a clean hosting IP with no DNSBL hits is usually fine for legitimate traffic.

How accurate is this check?

The DNSBL queries go to the same public lists the rest of the internet uses, so "listed" results are exactly what a receiving mail server would see. The geolocation data comes from ip-api.com, which is accurate to the city/region level for most countries. The composite score is a rough guide, not a guarantee: a single DNSBL hit does not mean your IP is unusable, and a clean score does not mean every other blocklist on the internet also agrees.
