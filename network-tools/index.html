About this toolbox

SiteTrace started as my own scratch pad of network utilities. I kept reaching for the same handful of lookups — "what does the internet see when I connect", "is this DNS change live yet", "is this service down for everyone or just me" — and every popular free site for those questions was either overloaded with ads, hiding the answer behind a signup form, or pushing a VPN upsell in your face. So I built SiteTrace the way I wanted it to work: open the URL, get the answer, close the tab.

Thirteen tools in five categories today, all running in your browser. Every tool is a single HTML page with the form, the result area, the schema.org JSON-LD, and a 2500-word supporting essay for SEO. There is no app to install, no account to create, no email to confirm. The site is funded by unobtrusive display ads and optional donations via PayPal — if it is useful to you and you want to keep it alive, the Support button at the top right is the way.

How the tools work, technically

Every browser-based tool on SiteTrace has the same architecture: a single HTML page that loads a small JavaScript module, which makes fetch() requests to public services and renders the result into the DOM. There is no SiteTrace server in the middle — your browser talks directly to ipwho.is and ip-api.com for IP geolocation, to Google and Cloudflare's DNS-over-HTTPS endpoints for DNS, and to the site you are checking for HTTP reachability. The only place a Cloudflare Worker sits in front is the service-status aggregator (because the Atlassian Statuspage API does not send CORS headers, so the Worker proxies the call and caches it at the edge for 60 seconds to stay within the free tier).

The page-internal JavaScript modules live in /js/ — one module per tool, plus a shared layout.js that wires the language switcher and a shared app.js for common UI patterns (toasts, copy-to-clipboard, refresh). The CSS is split between a top-level /styles.css with the shared utilities and an inline <style> block at the top of each page that defines the cyan design tokens, the grid background, and the page-specific overrides. There is no build step, no transpilation, no bundler — every file is what it is and you can read it.

Why browser-based instead of API-only

I chose browser-based for three reasons. First, no signup means more users actually use the tools — every page that asks for an email loses 40-60% of its visitors at the signup form, and I wanted SiteTrace to feel like Wikipedia, not a SaaS. Second, direct browser-to-service means lower latency for the answer — there is no extra hop through my Worker, so the round-trip is the round-trip. Third, no server in the middle means almost nothing to operate — Cloudflare Pages serves the static HTML for free, the DNS-over-HTTPS endpoints are run by Google and Cloudflare as a public good, and the only billable service is the status-aggregator Worker, which fits in the free tier.

That said, if you want to script these checks from CI, from a monitoring system, or from a server, the same logic is exposed as a paid JSON API at api.sitetrace.it.com. The free tier is no-signup + IP-rate-limited at 100 lookups per day, the Hobby tier is $9.99/month for 5,000/day, and the Pro tier is $30/month for 30,000/day. The free web tools stay free forever — paid users are funding them, not gating them.

Compared to MxToolbox, network-tools.webwiz.net, and centralops

The closest spiritual neighbors to SiteTrace are MxToolbox, network-tools.webwiz.net, and the original centralops.net Domain Dossier. MxToolbox is the deepest of the three — it goes way further into email deliverability, SMTP-level diagnostics, and blacklists than SiteTrace does, and if you are running a large mail server, MxToolbox is the right tool for you. Where SiteTrace differs is that it runs entirely in your browser (so you can use it without trusting MxToolbox's server with your query), it does not inject ads into the tool output, and it does not push an orange "MxToolbox Delivery Center" upsell card on every result page.

network-tools.webwiz.net is the cleanest of the three by visual standards — a categorized grid of 23 tools, scoped CSS, hand-rolled icons, no login. Where SiteTrace differs is that it bundles the tool output with a 2500-word supporting essay and schema.org JSON-LD for SEO, it has a paid API option for scripted lookups, and the design language (cyan + JetBrains Mono + IBM Plex Sans) is more engineer-focused than webwiz's generic sans-serif. Centralops.net still exists but the site is a literal 1995 frameset — the modern version is webwiz. SiteTrace sits somewhere between the two: more opinionated than webwiz, less deep than MxToolbox, friendlier than centralops.

Roadmap

Three things on the near-term list. First, more tools: traceroute (via a Cloudflare Worker that uses HTTP/3 timing), a port scanner (also Worker-proxied, with explicit rate limits so it can't be abused), and a TLS checker that surfaces the certificate chain, expiry, and cipher suite. Second, more languages — Chinese (Simplified), Indonesian, Vietnamese, and Swedish are already in the i18n dictionaries in draft form and need final review. Third, more service-status coverage — there are about 20 more services on my monitoring shortlist (Notion, Linear, Figma, Anthropic, Replit, Cursor, Supabase, Railway, Render, Fly, Vercel, Netlify, Stripe, Twilio, Cloudflare R2, Cloudflare Workers, AWS S3, GitLab, Bitbucket, JetBrains) that should each have their own card with live status. If you want to track progress, the changelog is in the GitHub repo.

Open source is not a marketing line — the whole site is MIT-licensed on GitHub, including the Cloudflare Worker for the status aggregator. You can read it, fork it, run it locally, or deploy your own copy with one click. If you find a bug or want to add a tool, pull requests are welcome. The repo lives at github.com/appenzellerdigitalstore-stack/sitetrace.

Frequently asked questions

Do I need to install anything to use these tools?

No. Every SiteTrace tool is a single HTML page that runs in your browser. There is nothing to download, no extension to install, no plugin to enable. Open the URL, get the answer, close the tab. The tools work on mobile too — the responsive layout was designed phone-first.

Is SiteTrace really free?

Yes, completely free, with no signup and no email gate. The site is funded by unobtrusive display ads and optional donations via PayPal. The same logic that powers the web tools is exposed as a paid API at api.sitetrace.it.com for users who want to script the checks — free tier is 100 lookups/day with no signup, paid tiers go up to 30,000/day.

Does SiteTrace log my IP address or my lookups?

No. SiteTrace does not run a server in the middle of your lookups — your browser talks directly to the public IP-geo or DNS-over-HTTPS services that answer your query. Cloudflare's standard edge logs cover the host layer; we do not record or read those logs at the application layer.

What is the difference between SiteTrace and MxToolbox?

MxToolbox goes deeper into email deliverability, blacklists, and SMTP diagnostics. SiteTrace covers the everyday lookups most developers actually need, runs entirely in your browser, and does not inject ads into the tool output. For email, SiteTrace parses SPF/DKIM/DMARC from DNS — but does not run SMTP-level tests.

Can I run these tools from a script or from CI?

Yes. The same logic is exposed as a JSON API at api.sitetrace.it.com. Free tier allows 100 lookups/day with no signup. Paid tiers allow much higher volumes and require an API key. Bulk email, bulk DNS, and bulk URL-status endpoints are all available.

Why does the IP lookup sometimes show the wrong city?

IP-based geolocation is approximate. The accuracy depends on your ISP's block size — large ISPs assign IP ranges that span entire regions, so the city shown is often the regional hub where your ISP has equipment, not your actual location. The tool shows the registered city, region, country, and the source ASN so you can tell whether the answer is from a residential block, a mobile carrier, or a hosting provider.

Are these tools open source?

Yes. The whole site is MIT-licensed on GitHub at github.com/appenzellerdigitalstore-stack/sitetrace. You can read it, fork it, run it locally, or deploy your own copy. Each HTML file is self-contained — no build step, no transpilation, no bundler.

How does the service status checker get its data?

From each service's official status page — most use Atlassian Statuspage, which exposes a public JSON API. SiteTrace fetches each summary through a Cloudflare Worker that handles CORS and rate limiting, then renders the result with a status dot and a 24-hour incident timeline. The reachability check on the Is It Down page runs in your own browser.
